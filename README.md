its_my_live

Отказоустойчивое системное решение для автоматического фонового мониторинга ресурсов в операционных системах семейства Debian, интегрированное с брокером сообщений RabbitMQ.

Проект разработан с фокусом на стабильность ("чтобы Debian не ложился раз в неделю") за счет изоляции среды выполнения, ротируемого логирования и жесткого лимитирования системных ресурсов.

Архитектура стабильности проекта

Изоляция окружения (venv): Все зависимости Python выполняются внутри изолированного виртуального контейнера в папке /opt/its_my_live, не забивая системный интерпретатор пакетов Debian.

Лимитирование ресурсов (cgroups): Созданная systemd-служба имеет встроенные жесткие ограничения на потребление памяти и процессора:

MemoryMax=128M — предотвращает утечки памяти и зависания ОС.

CPUQuota=15% — не позволяет процессу перегрузить ядра процессора.

Защита диска от переполнения: Логирование в файле its_my_live.log ограничено циклическим буфером (максимум 5 МБ на файл, хранятся 3 ротируемых бэкапа).

Устойчивость сетевого подключения: Скрипт снабжен автоматическим экспоненциальным переподключением к RabbitMQ на случай перезагрузок или сетевых сбоев.

Быстрый запуск (Полностью автоматическая установка)

Инсталляционный скрипт настроит абсолютно всё автоматически в «один клик». Он сам установит и запустит RabbitMQ из официальных источников, скачает зависимости Python, настроит виртуальное окружение и зарегистрирует службу systemd.

Выполните в консоли вашего Debian сервера:

# Клонирование репозитория
git clone [https://github.com/LAG-Lagendary/its_my_live.git](https://github.com/LAG-Lagendary/its_my_live.git)
cd its_my_live

# Предоставление прав на запуск инсталлятору
sudo chmod +x install.sh

# Запуск автоматической установки
sudo ./install.sh

Управление запущенным сервисом

После успешного выполнения install.sh, вы можете легко управлять службой стандартными системными утилитами:

Просмотр статуса работы:

sudo systemctl status its_my_live.service


Чтение логов в реальном времени:

sudo journalctl -u its_my_live.service -f


Перезапуск службы:

sudo systemctl restart its_my_live.service
